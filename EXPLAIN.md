# Как устроена система (для руководителя)

Это небольшая CRM для стройки: есть **объекты** (стройки) и **задачи** по ним. Пользователи входят по email и паролю. Регистрация с сайта закрыта — людей заводят вручную.

## Кто что может

**Постановщик** видит все объекты и задачи. Может создавать, править и удалять их, назначать исполнителя, принимать работу или возвращать на доработку (с обязательным комментарием).

**Исполнитель** видит только свои задачи и те объекты, где у него есть задачи. Может взять задачу в работу и отправить на проверку. Чужие задачи ему недоступны.

## Цикл задачи

Новая → В работе → На проверке → Принята  
или с проверки → На доработке → снова В работе.

Другие «прыжки» статусов система не принимает.

## Как защищены данные

Права стоят не только в кнопках на экране. Они записаны в базе (правила доступа Supabase). Даже если кто-то попробует обратиться к базе напрямую, минуя наш сайт:

- исполнитель не прочитает и не изменит чужие задачи;
- запрещённый переход статуса не пройдёт;
- историю смен статусов нельзя подделать, изменить или удалить через обычный доступ приложения.

Секретный ключ администратора базы во фронтенд и в репозиторий не попадает — в браузере только «публичный» ключ с ограниченными правами.
