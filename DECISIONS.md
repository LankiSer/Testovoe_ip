# Решения и допущения

## Решил сам (ТЗ допускало варианты)

1. **Стек UI:** Mantine (MIT) — быстрее собрать формы/таблицы/модалки за 2–3 часа.
2. **Фреймворк:** Next.js App Router + `@supabase/ssr` (удобный деплой на Vercel, cookie-сессии).
3. **Роль в `profiles.role` + `app_metadata.role` при создании пользователя.** Для RLS источник истины — таблица `profiles`, не `user_metadata` (его пользователь мог бы менять).
4. **Смена статуса только через RPC `transition_task`.** Прямой `UPDATE tasks.status` режется триггером.
5. **История:** insert при создании задачи (триггер) и при `transition_task`; у клиента нет политик insert/update/delete на историю.
6. **Редактирование полей задачи** (название, описание, исполнитель) — только постановщик; исполнитель меняет только статус по переходам.
7. **«Мои задачи»** доступны обеим ролям; у постановщика список пуст, если он не assignee (по ТЗ экран для исполнителя — оставили в меню всем для простоты навигации).
8. **Сиды:** 3 объекта, 6 задач в разных статусах; пользователи `manager@crm.test`, `executor1@crm.test`, `executor2@crm.test`.

## Не успели / вне минимального объёма

1. Автоотключение signup через Management API — сделать вручную в Dashboard: Authentication → запрет регистрации.
2. E2E-тесты и подробный audit log кроме истории статусов.
3. Загрузка файлов/вложений к задачам.
4. Уведомления на email при смене статуса.
